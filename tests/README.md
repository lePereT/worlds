# Tests

The tests are organised as a falsification history rather than as one feature suite.

```text
api.lua           v0.1 public surface and portable format names
core.lua          actuality, local supply, development, freshness, capture
certified.lua     opaque handles, provenance, immutable certified observation
separate.lua      frontiers, opaque linking, hidden identity correlation
frontier.lua      abstract Point rows and source-less specialisation
hostile.lua       concurrency, continuations, handlers, hidden state, custody
extreme.lua       joins, recursion, borrowing, existentials, cross-carrier identity
properties.lua    retirement, choice normalisation, locality, non-interference
```

The `stress_*.lua` files generate broader families of the same cases.

A new semantic mechanism should normally arrive with a hostile test showing why the existing geometry is insufficient. Tests which exposed a bad design should be kept even after the design is removed; they are part of the specification.
