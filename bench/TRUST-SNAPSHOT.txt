Encapsulation microbenchmark, 50,000 objects / 1,000,000 reads:

representation             construction      state reads      retained heap
weak-key registry            0.020413 s        0.107944 s       10103 KiB
single closure accessor      0.019312 s        0.134496 s       13133 KiB

The closure accessor is about 25% slower in this seven-run snapshot and retains
about 30% more heap. Other development runs put the read gap around 25-35%.
Weak-key private state is therefore used consistently for kernel and semantic
edge objects. The result is a representation choice, not a portable timing law;
other Lua implementations should be remeasured if they become deployment
requirements.

The ordinary query/search benchmarks move little because `_compiled` and the
query engine already consumed private zero-copy kernel observations. This change
primarily removes public/client-side allocation and defensive state recovery.
