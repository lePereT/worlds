# Candidate formed-computation calculus

The finite and recurrent transaction laboratories already give Relay two kinds of
semantic object:

1. completed finite relative Developments;
2. canonical Package roots naming open or recurrent Development meaning.

This laboratory adds no third executable ontology. It tests introduction and
elimination rules over those existing objects.

## Introduction

A formed computation value contains positive knowledge that it denotes semantic
root `R`. Any capture authority remains ordinary exact Geometry associated with
that value's surrounding Development.

Conceptually:

`form : PackageRoot x Captures -> FormedValue`

The root is portable denotation. Captures are exact occurrences and are fresh on
instantiation. Forming is inert: it neither fills the target Context nor adds
causal structure merely because the target root became known.

## Elimination

`perform` is an open Context with a value-targeted hole. The root needed to fill
that hole comes from positive knowledge about its first public value input.

Conceptually:

`perform : FormedValue -> target meaning`

When the root is established, the target definition is ordinary Package meaning.
For finite targets, each target alternative is plugged through the Context and
composed through the same finite Development calculus used elsewhere.

Performance is universal over admitted outcomes. If one target alternative cannot
compose with the continuation after the perform hole, the whole performance is
invalid. This is the semantic distinction between runtime possibility and
pre-commit search/specialisation.

## Higher order

A generic `run(op) = perform(op)` Context has no static dependency on a concrete
root. It therefore has stable portable identity of its own. Supplying different
formed values does not change what `run` means; it changes which semantic root its
value-targeted hole is able to close against.

A target may itself return a value denoting another root. One performance removes
one form layer only. Generated finite nesting and a work-returning-form pressure
show that this is structural, not a special two-level encoding. This provides
higher-order/nested computation meaning without an evaluator stack or automatic
flattening.

The same separately packaged performer can eliminate formed values denoting
unrelated roots with the same public interface. The performer root is independent
of those concrete targets. Alternatives remain families of correlated meanings;
performance preserves each target's correlated result knowledge rather than
constructing a common operation value.

## Wrapping without a handler ontology

Once positive knowledge establishes a formed value's target root, surrounding
`pre ; target ; post` structure is ordinary Context composition. The resulting
closed meaning may itself be packaged, formed and performed, with no handler node
or evaluator residue.

The stronger case where a wrapper's target remains selected by an input formed
value is intentionally left open. Such a Context can be packaged and formed, but
this finite layer returns `Deferred` when asked to eliminate it. It does not
synthesise new Package roots dynamically. Later target-resolution/viability work
must decide how that open semantic target closes.

## Authority

The root knowledge is epistemic. It may determine which target Geometry is
constructed, but that knowledge is not a causal edge. Causality arises only from
ordinary exact cuts, including cuts which connect captured Strands to the target
boundary.

## Deliberate finite boundary

The laboratory can transport a formed recursive root but does not decide its
infinite viability. Encountering any still-open target during finite perform returns `Deferred`. A
recursive target is one such case, but openness is not itself classified as
recurrence. Stage recurrence/target-resolution/viability work may later discharge
those questions without changing the `form` / `perform` meaning above.
