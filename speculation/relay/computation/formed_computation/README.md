# Transactional Formed Computation

This laboratory restores the original Fibers `Option` / `perform` insight at the
package-first Relay semantic level.

The thesis is:

> A formed computation is first-class portable semantic meaning. `form`
> introduces a value which denotes Package meaning and carries any captured exact
> authority through ordinary Worlds Geometry. `perform` eliminates that value by
> composing the denoted meaning into the surrounding computation. Neither
> operation adds a runtime AST, evaluator node, task object or new Worlds carrier.

The laboratory deliberately places this layer after finite transaction algebra
and Package/Context identity. A formed value needs a semantic root to denote;
`perform` is itself represented as a transportable open Context whose hole target
is obtained from positive value knowledge.

## Laboratory representation of Form knowledge

For the finite pressures here, `Form(value, root)` is represented by the existing
tiny equality doctrine as the value literal `semantic:sha256:...`. This is only a
finite executable stand-in for a restrictive occurrence-relative Form knowledge
domain. It is not a proposal that production Relay use ordinary strings as
computation values.

Captured authority is never placed in that knowledge. A formed value carrying
scarce authority has ordinary open Strands on its boundary. In this laboratory
the form interface convention associates the form's ordered authority outputs
with its single visible operation value; the Strands themselves remain the only
authority. Reusing one exact capture twice is rejected by ordinary Worlds
Construction.

## `form`

`form(root)` produces inert semantic meaning. It does not perform the target.
Its visible value denotes `root`; any captured authority is preserved as exact
boundary Geometry. Forming alone introduces no causal Face.

## `perform`

A generic performer is itself Package meaning. Its Context contains one semantic
hole whose target is the performer's first public value input. The Context can be
compiled and transported without knowing the concrete root.

When a formed value supplies that root, the hole is resolved and filled by
ordinary Development composition. For a finite target, the result contains no
`perform`, form wrapper, callback, continuation or evaluator residue.

Performance admits every current runtime alternative. Therefore a continuation
behind `perform` must compose with every admitted target outcome. A failing
continuation rejects the performance; it may not retroactively prune the runtime
branch which made it inconvenient.

This differs from uncommitted semantic selection before performance, where
ordinary finite-family specialisation may legitimately remove alternatives.

## Nesting

A performed computation may return another formed computation. One `perform`
removes exactly one layer. The inner form remains first-class meaning until an
explicit second performance. A generated finite nesting pressure now checks this
law through eight layers rather than relying on one hand-written double nest.

## Higher-order pressures

The extended pressures make four stronger claims explicit:

- one separately packaged `perform(op)` context is parametric over unrelated
  semantic roots with the same public interface; linking a new target does not
  change the performer root;
- alternative formed meanings retain branch-correlated result knowledge through
  performance; there is no invented union/computation value which forgets which
  facts belong to which outcome;
- ordinary work may return another formed computation without performing it, and
  scarce captures remain scarce after such higher-order passage;
- when a formed value's root is established, wrapper/handler-like structure is
  just ordinary Context composition followed by ordinary `form` / `perform`.

The laboratory deliberately does **not** claim that a completely generic
`wrap(op)` can manufacture a new closed Package root while `op`'s target remains
unknown. Such a value-targeted wrapper is valid open Package meaning and may itself
be formed and transported, but finite elimination returns `Deferred`. Later
target-resolution/viability work must discharge that open meaning without adding
an evaluator or runtime Package synthesiser.

## Recurrence boundary

A formed value may denote a recursive semantic root and transports that identity
unchanged. This finite laboratory does not unfold a recurrent target during
`perform`; it returns computational `Deferred` rather than confusing the missing
recurrence/viability engine with semantic `Retry` or `Unknown`. The next
recurrence/Judgement layers are responsible for that case.

## Constitutional pressures

The suite requires that:

- `form` is inert and transportable;
- `perform(op)` is itself separately compilable Package meaning;
- separately transported target, form and performer link by semantic root;
- finite `perform(form(target))` equals the target's ordinary Development meaning;
- root knowledge chooses Geometry without adding causality;
- runtime alternatives require a total continuation;
- a permissive continuation preserves all admitted alternatives;
- nesting is not implicitly flattened;
- captured scarce authority cannot feed two exact performances;
- one successful finite performance leaves no evaluator residue;
- a formed recursive root remains portable semantic identity and finite
  inability to unfold it is `Deferred`;
- arbitrary finite nesting removes exactly one form layer per explicit `perform`;
- ordinary work may return a still-unperformed formed computation;
- one separately compiled performer is root-parametric over unrelated targets;
- choice of formed meanings preserves branch-correlated results;
- established-root wrapper/handler-like composition uses ordinary Context
  composition, while a still-dynamic wrapper remains honestly open/`Deferred`;
- scarce capture authority survives higher-order passage without laundering;
- direct convenience execution can be defined as `perform(form(action))`
  without a second concurrency semantics;
- an incompatible formed target/interface is rejected by semantic composition,
  not by a computation type.
