# Transactional Development Calculus

This laboratory asks whether Relay can keep the strongest packaging property of old Relay while
retaining the semantic laws discovered by the radical transactional computation laboratory.

The experiment deliberately rejects the radical laboratory's mechanics. There is no opaque
`Comp` closure, no continuation callback, no transaction-context object in portable meaning, no
Package bytecode, no live search state, and no instruction which later manufactures a Development.

The thesis under test is:

> A finite Relay computation denotes a canonical ordered family of relative Developments.
>
> Each alternative is already symbolic Worlds Geometry plus positive Theory. Transactional
> composition transforms those semantic objects directly. A complete alternative is one Rule
> Development before judgement begins.

## Portable object

A laboratory Package contains:

- a finite family of relative Development alternatives;
- each alternative's symbolic Geometry;
- its positive Knowledge relation;
- marked public authority and value interfaces into that meaning;
- a dominance relation between alternatives.

The marked interface is boundary/presentation information. It is not executable code and does not
own authority. Preference is family judgement structure, not positive Geometry.

Canonical bytes and a content-derived semantic root are computed from this finite semantic form.
Instantiation freshens symbolic Geometry into exact Worlds occurrences.

## Tiny equality domain used here

This laboratory intentionally uses only a positive equality domain over literal/value variables.
The domain implements the four-operation contract (`equal`, `meet`, `reindex`, `exists`) and runs on
the shared thin Knowledge host. This is enough to pressure packaging and dependent composition
without smuggling a theorem engine into the model.

The value relation here is one symbolic equality domain running on the shared thin Knowledge host.
It is **not** another Theory host. In particular this laboratory does not
itself exercise every occurrence-supported domain. Native Construction-correspondence transport
is exercised by the later restrictive-Knowledge and recursive-viability laboratories.

## Operators

`always` and value identity are pure relative Developments.

`or` is unordered family union.

`or_else` adds dominance and stores its transitive partial order canonically.

`each` is a true n-ary Cartesian product of families. Selected alternatives are positively joined
with no sibling equations.

`bind` is direct semantic composition. The left published value relation is conjoined with the
right input relation and the intermediate value is existentially projected away. No causal edge is
created by this knowledge dependency. Explicit authority capture adds exact Strand cuts and only
those cuts create causal Geometry.

`together` forms the whole n-ary sibling tuple, asks ordinary Worlds Close for lawful sibling cuts,
and preserves every lawful closure as an alternative.

There is no `perform` or evaluator in Package. A tiny `prepare` helper exists only for two exact
scarcity/eligibility pressures; it consumes already-complete Package alternatives.

## Link normalisation

The research linker currently uses fresh exact Worlds occurrences as disposable normalisation
evidence: instantiate the symbolic parts, ask Worlds Construction/Close for the exact quotient,
then erase every exact identity back to canonical symbolic Geometry before hashing or transport.

This is an implementation technique, not Package meaning. Native Construction correspondence is
used to order the symbolic quotient by its marked source classes, rather than by fresh result
allocation order. The tests repeatedly relink fresh occurrences and require identical bytes and
roots.

A production compiler could later replace this with a direct symbolic quotient algorithm without
changing the semantic Package format.

## Constitutional pressures

The laboratory requires that:

- separate compilation and serialisation precede composition without changing meaning;
- alpha/debug names do not enter semantic identity;
- fresh instantiation never reuses exact Worlds identity;
- knowledge-only bind is noncausal;
- authority capture alone creates causality;
- failed descendants leave no preference residue;
- `each` uses the Cartesian product order rather than lexicographic nesting;
- `together` is whole-sibling and preserves ambiguity;
- alternatives may share one scarce live source while positive siblings may not duplicate it;
- finite value-dependent shape can remain an extensional family of Developments;
- completed alternatives contain no trace, continuation or transaction state;
- bind identity and associativity hold canonically, including explicit authority capture;
- repeated hidden dependent history contracts back to extensional meaning;
- exact occurrences minted by the linker cannot perturb Package identity;
- canonical Geometry cannot retain composition parenthesisation or compilation scale.

## Deliberate boundary: recurrence

The finite calculus still has no `fix` implementation. This is intentional. Recurrence now lives in
a sibling research layer as finite cyclic Package topology over these finite Development contexts,
not as another operator in this calculus.

Building that sibling exposed one finite normal-form defect: source-relative Construction provenance
alone did not erase composition parenthesisation after longer authority chains. `Template.normal` now
applies a structural Geometry alpha-normal form with the marked authority boundary, and pressure 30
requires left- and right-associated compilation to agree through eight stages.

The later restrictive-Theory laboratories supply occurrence-relative domains over the same thin host;
this early calculus intentionally needs only symbolic value equality.

## Open-boundary occurrence support

The concurrency arena now uses a more general open-boundary representation than the earlier
match-signature prototype.  A relative Development may mark selected public authority positions as
open to sibling closure, while ordinary positive Knowledge facts are supported directly on the
corresponding symbolic Strands.

When `C.together` selects a cut, Knowledge is transported through native Construction correspondence
classes before any vanished support is hidden.  This matters because a closed SCC may annihilate a
matched Strand even though the source quotient still carries the knowledge needed to validate the
closure.

The open selection and the supported knowledge remain distinct: knowing facts about an occurrence
does not itself authorise sibling closure.  The record-shaped support used by this finite calculus is
research scaffolding for the broader occurrence-relative Knowledge contract, not a proposed production
Theory representation.
